# MoneyBasket — ТЗ для Claude Code

> Личное PWA-приложение для учёта «корзин» — денег, которые откладываются с зарплаты под конкретные цели (Крупные покупки, Отпуск, Крипта и т.д.).
> Заменяет ведение корзин в текстовых заметках.
> Ежедневные «карманные» расходы остаются в отдельном трекере и в этом приложении **не ведутся**.

---

## 1. Контекст и проблема

Сейчас каждый месяц создаётся текстовая заметка: доходы, по каждой корзине — «Осталось с прошлого месяца», список операций, «Осталось на DD.MM». Остатки пересчитываются вручную.

Боли, которые должно снять приложение:

1. **Ручной пересчёт остатков** — каждый «Осталось на…» считается руками, ошибки находятся случайно («откуда-то взялись лишние деньги»).
2. **Одна корзина — много мест и валют.** Отпуск одновременно лежит на расчётном счёте (BYN), на евро-карте (EUR), на дебетовой карте (USD), наличкой в копилке (USD, EUR) и на накопительном счёте (BYN).
3. **Одно место — много корзин.** На накопительном счёте одновременно лежат деньги Крупных покупок, Отпуска, Крипты и отложенные отпускные. Реальный остаток в банке нужно сверять с суммой по корзинам.
4. **Займы.** «Одолжил Ане 85р из крупных покупок», «120р брату до осени», «взял 210р со счёта в карманные, потом верну» — сейчас это строки с `!!!` и зачёркивания.
5. **Обмены валют** внутри корзины и даже между корзинами («продаю из крупных покупок 275,40$ за 820р из крипты»).
6. **Нет общей картины**: сколько всего в корзине в BYN/USD, как она менялась.

## 2. Цели MVP

- Внести любую типичную операцию из заметок **за ≤ 15 секунд с телефона**.
- Остатки по корзине × месту × валюте считаются автоматически и **совпадают с ручным расчётом** (см. золотые тесты, раздел 9).
- Видно, какие займы открыты и из какой корзины.
- Данные не теряются: локальное хранение + экспорт/импорт JSON.

**Вне скоупа MVP:** карманные расходы с категориями (остаются в отдельном трекере), учёт криптокошельков и BTC-позиций, импорт истории из заметок, синхронизация между устройствами, мультипользовательность, банковские интеграции.

## 3. Платформа и стек

| Что | Решение |
|---|---|
| Тип | PWA, mobile-first, устанавливается на домашний экран, работает офлайн |
| Фреймворк | Vite + React + TypeScript (strict) |
| Хранение | IndexedDB через Dexie.js (+ `dexie-react-hooks` / `liveQuery` для реактивности) |
| Стили | Tailwind CSS; тёмная и светлая тема по системной |
| PWA | `vite-plugin-pwa` (manifest, service worker, офлайн-кэш ассетов) |
| Тесты | Vitest для доменной логики; Playwright — один smoke e2e на основной сценарий |
| Хостинг | Любой статический HTTPS-хостинг (Cloudflare Pages / GitHub Pages). Данные на сервер не уходят |
| Язык UI | Русский. Формат чисел `ru-RU`: `1 234,56`. Ввод принимает и `,`, и `.` |
| Часовой пояс | Europe/Minsk. Даты операций хранить как `YYYY-MM-DD` (без времени), `createdAt` — ISO |

Без бэкенда, без авторизации. Новые зависимости сверх списка — только если без них никак, с объяснением в коммите.

### Риски хранения на iOS (обязательно учесть)
- Safari может очистить IndexedDB у сайтов, которыми давно не пользовались. Установленное на домашний экран PWA защищено лучше, но не гарантированно → при старте вызывать `navigator.storage.persist()` и показывать статус.
- Данные «сайта в Safari» и «PWA с домашнего экрана» — **разные хранилища**. На экране онбординга предупредить: пользоваться только установленной версией.
- Напоминание о бэкапе: если последний экспорт был > 7 дней назад — баннер на главной.

## 4. Предметная модель

### 4.1 Понятия

- **Корзина (Bucket)** — цель накоплений: Крупные покупки, Отпуск, Крипта. Настраиваемый список. Плюс системная корзина **«Нераспределено»** — для денег, которые уже получены, но ещё не разложены (например, отпускные, переезжающие на следующий месяц).
- **Место хранения (Location)** — где физически лежат деньги: Накопительный, Валютная карта, Расчётный счёт, Евро-карта, Дебетовая карта, Наличка, Копилка, Дача, Биржа… Тип: `bank`, `cash`, `exchange`.
- **Контрагент займа** — тоже место хранения, тип `receivable`: «Долг: Аня», «Долг: Брат», «Долг: Карманные». Выдача займа = перемещение денег из реального места в место-долг **внутри той же корзины**. Поэтому займ остаётся частью корзины (как в заметках: «85р отдолжил Ане» в списке остатков), а возврат — обратное перемещение.
- **Валюта** — BYN, USD, EUR, USDT (список расширяемый). У валюты есть число знаков после запятой.
- **Позиция (Holding)** — остаток по тройке *корзина × место × валюта*. **Не хранится**, а вычисляется как сумма проводок.
- **Операция (Operation)** — одно действие пользователя (расход, обмен, займ…). Состоит из 1..N **проводок (Entry)**.

### 4.2 Схема данных (Dexie)

```ts
type CurrencyCode = 'BYN' | 'USD' | 'EUR' | 'USDT' | string;

interface Currency { code: CurrencyCode; symbol: string; decimals: number; usdPeg?: boolean } // USDT: usdPeg=true

interface Bucket {
  id: string; name: string; emoji?: string; color?: string;
  system?: 'unallocated';           // только для «Нераспределено»
  target?: { amount: number; currency: CurrencyCode }; // этап 3
  archived: boolean; sort: number;
}

interface Location {
  id: string; name: string;
  kind: 'bank' | 'cash' | 'exchange' | 'receivable';
  counterparty?: string;            // для receivable
  archived: boolean; sort: number;
}

type OperationType =
  | 'opening'        // стартовый остаток
  | 'topup'          // пополнение корзины (с ЗП, аванса, из карманных, подарок…)
  | 'expense'        // трата из корзины
  | 'move'           // перемещение между местами внутри корзины
  | 'exchange'       // обмен валют внутри корзины
  | 'reallocate'     // перевод между корзинами (в т.ч. встречный обмен)
  | 'loan_out'       // выдача займа (move в receivable)
  | 'loan_return'    // возврат займа (move из receivable)
  | 'to_pocket'      // безвозвратно отдал в карманные
  | 'invest_out'     // вывод в крипту/на кошелёк — деньги уходят из учёта
  | 'adjustment';    // корректировка по результатам сверки

interface Operation {
  id: string;
  type: OperationType;
  date: string;                     // YYYY-MM-DD
  description: string;              // «Отель», «Курсы», «BTC»
  tag?: string;                     // опционально: Подарки, Здоровье, Английский, Техника, Поездки…
  source?: 'salary' | 'advance' | 'vacation_pay' | 'pocket' | 'gift' | 'rent_income' | 'other'; // для topup
  meta?: {
    rate?: number;                  // для exchange: сколько отдано за 1 ед. полученной валюты
    fee?: number;                   // комиссия (в валюте списания)
    dueDate?: string;               // для loan_out
    receivedAsset?: string;         // для invest_out: «0.0012 BTC», «180 USDT на кошелёк»
  };
  createdAt: string; updatedAt: string; deletedAt?: string;  // мягкое удаление
}

interface Entry {
  id: string; operationId: string;
  bucketId: string; locationId: string; currency: CurrencyCode;
  amount: number;                   // целое, в минорных единицах (копейки/центы), со знаком
}

interface IncomeRecord {             // журнал доходов месяца (информационный)
  id: string; date: string;
  month: string;                    // YYYY-MM — к какому месяцу относится (отпускные могут переезжать)
  kind: 'advance' | 'salary' | 'vacation_pay' | 'rent_income' | 'other';
  amount: number; currency: CurrencyCode; note?: string;
}

interface Rate { date: string; currency: CurrencyCode; bynPerUnit: number; source: 'nbrb' | 'manual' }

interface AllocationTemplate {       // этап 2
  id: string; name: string;         // «Аванс», «ЗП 20 числа»
  lines: { bucketId: string; locationId: string; mode: 'fixed' | 'percent'; value: number }[];
}

interface Settings { baseCurrency: 'BYN'; secondaryCurrency: 'USD'; lastBackupAt?: string; hideAmounts: boolean }
```

**Деньги — только целые числа в минорных единицах.** Никаких float в хранении и расчётах. Форматирование — в одном модуле.

### 4.3 Правила проводок (инварианты)

| Тип | Проводки | Инвариант |
|---|---|---|
| opening | +X в (корзина, место, валюта) | — |
| topup | +X | — |
| expense | −X, можно несколько строк («Цветы 128р: 120р наличкой + 8р с накопительного») | все строки одной корзины |
| move | −X из места A, +X в место B | одна корзина, одна валюта, сумма = 0 |
| exchange | −A (валюта 1), +B (валюта 2), опц. −fee | одна корзина, ровно 2 валюты |
| reallocate | −X в корзине A, +X в корзине B; опционально встречная часть | сумма по каждой валюте = 0 |
| loan_out / loan_return | move между реальным местом и receivable | одна корзина, сумма = 0 |
| to_pocket, invest_out | −X | — |
| adjustment | ±X | обязательно описание |

Валидация — в доменном слое, не в UI. Уход позиции в минус **не блокирует**, а показывает предупреждение (на практике такое бывает временно).

Пример встречного перевода «продаю из Крупных покупок 275,40$ на валютной карте за 820р из Крипты»:
```
КП:     Валютная карта USD −275,40      Крипта: Валютная карта USD +275,40
Крипта: Накопительный   BYN −820,00      КП:     Накопительный   BYN +820,00
```

Редактирование и удаление операций разрешено; остатки всегда пересчитываются из проводок. Удаление — мягкое, с «Отменить» в тосте 5 секунд.

## 5. Экраны

### 5.1 Главная
- Сверху — общий итог по всем корзинам в BYN и ≈ USD (по последнему курсу). Кнопка-глаз «скрыть суммы».
- Карточки корзин: название, итог в BYN и ≈ USD, под ним компактно позиции (как блок «Осталось на…» в заметках): `1 234,56 р · Накопительный`, `385 $ · Копилка`, `120 р · Долг: Брат`.
- Бейдж, если в корзине есть открытые займы.
- Большая кнопка «+» — быстрый ввод.
- Баннер «Сделай бэкап», если нужно (см. 3).

### 5.2 Быстрый ввод операции (главный экран по частоте использования)
- Тип по умолчанию — **Расход**. Переключатель типов: Расход · Пополнение · Перемещение · Обмен · Займ · Ещё (перевод между корзинами, в карманные, вывод в крипту, корректировка).
- Порядок полей: сумма (сразу фокус, цифровая клавиатура) → корзина (чипы) → место (чипы, сначала места, где в этой корзине есть деньги, с остатком рядом) → валюта (подставляется из места, если там одна валюта) → описание (автодополнение из прошлых описаний) → дата (сегодня / вчера / выбрать).
- Запоминать последние корзину и место для каждого типа.
- «+ ещё место оплаты» — для раздельной оплаты.
- Обмен: «отдал» (место, валюта, сумма) → «получил» (место, валюта, сумма) → курс считается и показывается; комиссия опционально.
- Займ: выбор контрагента (или создать нового), срок возврата опционально. Возврат: список открытых займов → «вернули частично / полностью» → куда пришли деньги.
- После сохранения — тост с итоговым остатком позиции и кнопкой «Отменить».

### 5.3 Корзина
- Позиции (место × валюта) с суммами, итог в BYN/≈USD.
- Лента операций с фильтром по месяцу, группировка по дням.
- Внутри месяца: «было на начало → пополнения → расходы → стало».

### 5.4 Места хранения
- Для каждого места: сколько в нём денег по валютам и из каких корзин.
- **Сверка**: ввожу фактический остаток из банковского приложения → приложение показывает расхождение → одной кнопкой создаю корректировку, выбрав, какой корзине её отнести.

### 5.5 Займы
- Открытые займы: кто, сколько, из какой корзины, дата, срок (просроченные подсвечены).
- Закрытые — свёрнутым списком.

### 5.6 Месяц (этап 2)
- Доходы месяца (IncomeRecord): аванс, ЗП, отпускные, доход с квартиры, итого.
- По каждой корзине — отчёт в структуре заметок: «Осталось с прошлого месяца» → операции → «Осталось на конец».
- **Экспорт месяца в Markdown** в формате, близком к ручным заметкам, — чтобы архив заметок продолжал жить.

### 5.7 Распределение зарплаты (этап 2)
- Ввожу доход (тип, сумма, дата, к какому месяцу).
- Выбираю шаблон («Аванс» / «ЗП»): строки корзина → место → фикс. сумма или % → предпросмотр, остаток «в карманные» считается автоматически. Суммы можно поправить перед сохранением.
- Часть дохода можно отправить в «Нераспределено» (случай с отпускными, которые переезжают на следующий месяц) и разложить позже.
- Сохранение создаёт IncomeRecord + пачку операций `topup`.

### 5.8 Настройки
- Корзины, места, контрагенты, валюты: создать / переименовать / упорядочить / архивировать (удаление запрещено, если есть проводки).
- Шаблоны распределения.
- Курсы: авто-загрузка с API НБРБ (`https://api.nbrb.by/exrates/rates/{USD|EUR}?parammode=2`), кэш последнего значения, ручной ввод как запасной вариант. USDT считать = USD. Если API недоступен из браузера (CORS/офлайн) — работать на последнем сохранённом или ручном курсе, не падать.
- Экспорт всей базы в JSON (файл с датой в имени через Web Share API / скачивание), импорт JSON с подтверждением и полной заменой данных. Формат экспорта версионирован (`schemaVersion`).
- Статус `storage.persist()`.

### 5.9 Онбординг (первый запуск)
1. Предупреждение про установку на домашний экран.
2. Создание корзин (предзаполнено: Крупные покупки, Отпуск, Крипта + системная «Нераспределено»).
3. Создание мест (предзаполнено списком из раздела 4.1, лишнее можно удалить).
4. **Ввод стартовых остатков**: таблица корзина → [место, валюта, сумма] (+ открытые займы). Создаёт операции `opening` на выбранную дату.

## 6. Нефункциональные требования
- Мобильный экран 375 px — основной. Кнопки ≥ 44 px, основные действия в нижней трети экрана.
- Холодный старт < 1 с на современном телефоне; работа полностью офлайн.
- Никакой телеметрии и внешних запросов, кроме курсов НБРБ.
- Доменная логика (расчёт остатков, валидация, конвертация, форматирование) — чистые функции в `src/domain/`, без React и Dexie, со 100 % покрытием ключевых сценариев тестами.

## 8. Этапы

**Этап 0 — каркас (полдня).** Vite + TS + Tailwind + PWA + Dexie + Vitest. Доменная модель и расчёт остатков с золотыми тестами. Деплой пустого PWA и установка на телефон — чтобы с первого дня проверять на реальном устройстве.

**Этап 1 — MVP (цель: начать вести корзины в приложении вместо заметок).**
Онбординг со стартовыми остатками · Главная · Быстрый ввод: расход, пополнение, перемещение, обмен, займ/возврат, в карманные · Экран корзины · Экран займов · Редактирование/удаление операций · Экспорт/импорт JSON · Напоминание о бэкапе.

**Этап 2 — удобство.**
Распределение зарплаты по шаблонам · «Нераспределено» · Журнал доходов · Месячный отчёт + экспорт в Markdown · Места хранения и сверка с корректировкой · Курсы НБРБ и эквиваленты в BYN/USD · Перевод между корзинами со встречной частью · Вывод в крипту.

**Этап 3 — потом, если захочется.**
Цели корзин с прогресс-баром · Аналитика расходов по тегам и динамика корзин по месяцам · Напоминания (например, о регулярных покупках) · PIN-блокировка · Синхронизация между устройствами.

## 9. Критерии приёмки и золотые тесты

Каждый сценарий — Vitest-тест в `tests/golden/`, который прогоняет операции через доменный слой и сверяет остатки до копейки.

### Тест 1. «Крупные покупки»
Стартовые остатки:
| Место | Сумма |
|---|---|
| Накопительный | 1 284,36 BYN |
| Наличка | 760 BYN |
| Долг: Аня | 85 BYN |
| Долг: Брат | 120 BYN |
| Дача | 410 USD |
| Копилка | 385 USD |
| Копилка | 175 EUR |

Операции:
1. move 280 BYN Наличка → Накопительный
2. expense 15,50 BYN Накопительный «Канцтовары»
3. loan_return 85 BYN Долг: Аня → Накопительный
4. expense 18,40 BYN Накопительный «Такси»
5. expense 645,30 BYN Накопительный «Отель»
6. expense «Цветы» раздельно: 120 BYN Наличка + 8 BYN Накопительный
7. expense 19,90 BYN Накопительный «Такси»

Ожидаемо в конце: Накопительный **942,26 BYN**, Наличка **360 BYN**, Долг: Аня **0** (займ закрыт), Долг: Брат **120 BYN**, Дача 410 USD, Копилка 385 USD и 175 EUR.

### Тест 2. «Отпуск», несколько валют
Старт: Копилка 260 EUR и 610 USD, Евро-карта 385,40 EUR, Расчётный счёт 1 750 BYN, Дебетовая карта 318,75 USD.
Операции: move USD Дебетовая карта → Копилка: 65, 85, 45, 80; topup 620 BYN Накопительный (source=advance); topup 310 BYN Накопительный (source=salary).
Ожидаемо в конце: Копилка **885 USD** и 260 EUR, Дебетовая карта **43,75 USD**, Накопительный **930 BYN**, Расчётный счёт 1 750 BYN, Евро-карта 385,40 EUR.

### Тест 3. Обмен

## 10. Как работать (для Claude Code)
- Начинать с `src/domain/` и золотых тестов; UI — после того, как тесты зелёные.
- Идти по этапам; в конце каждого этапа — рабочая сборка, задеплоенная и проверенная на телефоне.
- Коммит на каждую законченную фичу, понятные сообщения.
- Непонятное в предметной области — сначала сверяться с золотыми тестами, если не помогло — спросить, а не придумывать.
- Не добавлять функции вне текущего этапа без запроса.
